Open URL Redirection

An unvalidated redirect parameter tricks users into trusting a link originating from a legitimate site that silently hands them over to an attacker.

Sandbox Defense Controller

● Vulnerable Mode Active — Unchecked target redirection

SECTION 01

What it is

Open Redirection (OWASP A01:2021 • CWE-601) occurs when an application accepts untrusted input via parameters like ?next= and redirects visitors without destination validation. Phishing attacks exploit this because the initial link points to a trusted domain, deceiving victims and bypassing email security filters.

SECTION 04

Why it matters

Open redirects turn reputable domains into attack vectors for credential theft. Users assume links on trusted domains are safe, landing on credential harvesting forms.

Real-World Incident: In 2021, cybercriminals exploited unvalidated redirects on American Express and Snapchat landing pages to orchestrate widespread Microsoft 365 credential harvesting attacks.

Open Redirect

CWE-601 OWASP A01:2021 — Broken Access Control
← Clickjacking Next: DOM Clobbering →

1 What It Is

An open redirect happens when a web app takes a URL from a query parameter and redirects the user to it without checking where it leads. Attackers exploit this to craft links that start with a trusted domain but end up on a phishing site. Because the link looks legitimate, victims click it without suspicion.

2 The Vulnerable Code

After login, the server blindly redirects to whatever URL is in the redirect parameter.

login-handler.js 
const express = require('express');
const app = express();

app.post('/login', (req, res) => {
  // ... validate credentials ...

  const redirectUrl = req.query.redirect;

  res.redirect(redirectUrl);  // ← No validation!

});

Why it's dangerous: res.redirect(redirectUrl) sends the user wherever the redirect parameter says — including https://evil-phishing.com. There is zero validation of the destination URL.

4 Why It Matters

Open redirects are phishing force multipliers. An attacker sends a link like https://trusted-bank.com/login?redirect=https://evil.com — the victim sees the trusted domain and clicks. They log in, get redirected to a fake page, and enter their credentials a second time thinking the first attempt failed.

Real incident: In 2016, a Google open redirect vulnerability (google.com/url?q=…) was used in phishing campaigns that targeted Gmail users. Attackers used it because email security filters trusted links starting with google.com.

5 The Fix

Validate the redirect URL against a whitelist of allowed domains before redirecting.

login-handler-fixed.js 
const ALLOWED = ['trusted-bank.com', 'cdn.myapp.com'];

function isAllowedRedirect(url) {
  try {
    const parsed = new URL(url);
    return ALLOWED.includes(parsed.hostname);  // ← whitelist check
  } catch {
    return false;
  }
}

app.post('/login', (req, res) => {
  const url = req.query.redirect;
  if (isAllowedRedirect(url)) res.redirect(url);
  else res.redirect('/');  // fallback to home
});

Why it works: The URL constructor safely parses the redirect target. parsed.hostname is then checked against the allowlist. Invalid URLs, protocol-relative tricks, and @-sign bypasses all fail the check, and the user is sent to the homepage instead.
